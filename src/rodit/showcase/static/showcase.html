    判断层 · 路由

  2. 2找依据

    知识中心 + 平台工具

    商品知识、店铺政策，加上订单、物流、售后的实时数据；冲突时高优先级覆盖。

  3. 3写回答

    FAQ / 模板优先，其次大模型

    只根据找到的依据写，回答带依据 ID；依据里没有的，不猜。

  4. 4把关

    硬规则 + 判断层质检

    有没有依据、是否答非所问、有没有承诺风险、是否违反平台话术规则。

  5. 5兜底

    人工客服

    拿不准的交给人；情绪激动、投诉先提醒客服；售后操作必须由人确认。

调研后决定架构的三个发现

方案 §0、§2.2

01

智能辅助是三个平台都走得通的路

全自动接待准入严格，抖店、拼多多没有查到公开的消息收发接口。AI 起草、客服一键发送，在淘宝和抖店计为人工回复，反而改善平台的客服考核指标。

02

数据必须留在平台云里

淘宝要求入驻聚石塔，拼多多的订单和售后接口要在多多云内调用，抖店有抖店云。所以每个平台单独部署一个单元，买家数据不跨云、不出境。

03

保留 Jev 的接口，先用境内实现

判断层内部统一用 Jev 的请求和响应格式（noul / choice / score + 概率）。买家消息不能发往境外；满足 §6.3 的条件后，只换一个实现就能接回 Jev。

        站外引流

        微信、手机号、QQ、链接、二维码、"加我"……抖店、拼多多明确禁止，违规扣分（§2.1）。

        绝对化用语

        "最""第一""绝对""100%"等，商家可以补充；如实的成分标注（"桑蚕丝 100%"）放行。

        依据《广告法》和虚假宣传相关规定（§12.3）

        虚假承诺

        依据之外的价格、赠品、到货时间、赔偿；回答里的数字必须能在依据里找到。

        "亲，明天一定能到哦！" → 拦截，改成只说物流事实（§11.5）

        商家禁用词

        店铺政策里的禁用词和商品上标注的"不能说的卖点"（比如没有检测报告的"防晒"）。

        质检时一并检查（§5.2.2、§5.5）

        判断层与 Jev：接口兼容，先用境内实现

        路由和质检都是"判断题"，统一用 Jev 的三种题型：noul 是否、choice 多选一、score 打分，每个答案带概率（§6.1、§6.5）。

        买家消息发给 Jev 会流向境外处理方，和平台"不得转委托他人处理个人信息"的规则、个人信息出境的法律要求冲突（§6.2），所以生产上先用平台云内的境内大模型投票 + 规则兜底。

        满足 §6.3 的四个条件（境内 / 私有化部署、公开运营主体和数据处理协议、通过平台报备、中文效果达标）后，只换一个实现就能接回 Jev，编排、阈值、审计都不用改。

        不用 RPA、模拟登录

        RPA、模拟登录、逆向客户端、抓包，一律不用（§2.4）。平台安全规范禁止用爬虫和插件获取用户数据，违规服务商会被清退，商家店铺会被扣分甚至封店。

        拼多多暂时没有查到客服消息开放接口，就先做模式 C 独立话术助手：客服把买家的问题粘贴进来，拿到推荐后自己复制回去，不做任何自动抓取（§8.1）。

        以上不构成法律意见，涉及合规判断的地方建议法务确认。

        演示站使用合成数据和离线大模型替身；生产部署在各平台云内（方案 §9.1）
